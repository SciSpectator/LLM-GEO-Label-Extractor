# Package layout

Everything the paper reports is here: the corpus, the code that produced it, the
prompts, the evaluation scripts with their results, and harnesses that check the
three claims a reader would want to test.

## The corpus

| Path | What it is |
|---|---|
| `data/06_final_labels_repaired/LLM_labels_all_samples_FINAL.csv.gz` | **the corpus the paper reports** — 804,427 samples |
| `data/05_final_labels/LLM_labels_all_samples.csv.gz` | the first extraction pass, kept so the correction is traceable |

The reported corpus is the first pass with the re-extracted samples substituted
in: same samples, same columns, corrected labels for 59,728 of them. It is the
output of the extraction runs and is not edited after the fact. Rebuild it and
compare if you want to check that:

```bash
python3 data/06_final_labels_repaired/scripts/build_final_corpus.py \
        data/05_final_labels/LLM_labels_all_samples.csv.gz \
        <jobA_condition.csv.gz> <jobB_full.csv.gz> /tmp/rebuild.csv.gz
```

## The code

| Path | What it is |
|---|---|
| `code/1_extraction_phase1_1b`, `code/2_normalization_phase2`, `code/4_final_assembly` | the code of the first pass |
| `code/5_repaired_pipeline` | the repaired code, which produced the re-extracted samples |

Phase 1 is byte-identical between the two. Phase 2 differs in six files and adds
three; `code/5_repaired_pipeline/README.md` lists the repair per function and
`PROVENANCE.md` gives the size of each change.

```bash
diff -rq code/1_extraction_phase1_1b code/5_repaired_pipeline/phase1
diff -rq code/2_normalization_phase2 code/5_repaired_pipeline/phase2
```

## The prompts

`prompts/` holds every prompt as plain text, one file each, grouped by stage:
`01_phase1` (5), `02_phase1b` (3), `03_phase2` (6), `04_judge` (the two
LLM-judge protocols), `05_repaired` (the one prompt the repair changed — the
short-form stage, which gained an explicit output contract).

## Re-extraction outputs

`data/07_reextraction_outputs/` holds what the two corrective runs produced,
before merging:

* `acronym_normalisation/` — the repaired Phase 2 over the unchanged Phase 1
  output, for the acronym instances the first pass left unresolved;
* `integrity_reextraction/` — the samples the integrity screens flagged,
  re-extracted end to end, with the assembled labels and the screen verdicts.

`data/06_final_labels_repaired/phase2_out/` is the merged Phase 2 output that
the evaluation scripts read, with both the post-fold and pre-fold dictionaries.

## Evaluation

One folder per table under `data/evaluation/`, each holding its script, its
result and a README with the exact command. Seven tables have no folder because
they carry no independent measurement -- S2, S4 and S15 re-tabulate counts held
elsewhere, S3 is recomputed from the Phase 1/1b outputs, S16 and S18 re-present
Table 1/S1 and S5, and Table 2 is S5's instance rows; `data/evaluation/README.md`
names the source of each. Everything else recomputes from the corpus.

`data/06_final_labels_repaired/evaluation/` holds the same results collected in
one place, plus the JSON summaries the manuscript figures were written from.

`data/evaluation/error_analysis/` is what the main text's Error analysis section
is written from: the errors that survive in the released corpus, per label, each
tagged with whether it comes from the record not stating the fact, from
extraction, from normalization, or from an unresolved acronym.
