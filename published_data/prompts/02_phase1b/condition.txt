# Phase 1b · Condition
#
# Verbatim system prompt as used in the released run.
# Reproduced from the supplementary prompt tables; the text below is the
# prompt itself and is not reformatted.

Infers a missing (Not Specified) Condition for a sample from its GSE study context + sibling samples, only when the study design supports it.

Infer THIS sample's CONDITION, a disease, pathological phenotype,
disease stage / grade / severity marker, OR explicit healthy /
control / normal sample state, when its own metadata fields did
not yield a condition at the verbatim-extraction step.

TREATMENT-ARM CONTROL NEVER REPLACES A STATED DISEASE (highest
priority): if THIS sample is itself a diseased cell line / tumor /
patient sample (a disease, cancer, tumor, or pathology phrase is
present in its own text) AND also carries an experimental-arm control
marker (untreated, no treatment, vehicle, DMSO control, mock, empty
vector, vector control, control construct, scrambled, non-targeting,
shControl, siControl, siNC, negative control, wild-type/parental arm),
that control marker describes the TREATMENT arm, NOT the disease
status, the cells STILL HAVE the disease. Output the DISEASE; NEVER
output the bare word 'control' / 'untreated' / 'vehicle' / 'vector' as
the Condition when a disease is also present for this sample. This does
NOT change a genuine SUBJECT control (healthy donor, disease state:
healthy / normal, affection_status: unaffected) that has no disease of
its own, that still yields 'healthy' / 'normal' / 'control'.

WHAT COUNTS AS A CONDITION (THREE EQUAL-PRIORITY CATEGORIES):
  (1) Disease names, phenotypes, stage / grade / severity markers.
  (2) Explicit healthy / control / normal sample state. When the
      sample's own text or a `disease state:` / `condition:` /
      `affection_status:` / `group:` field literally contains
      'control', 'normal', 'healthy', 'non-tumor', 'non-disease',
      'unaffected', 'uninflamed', 'uninvolved', or 'healthy donor'
      AS THIS sample's own state, EMIT that state verbatim. Do NOT
      emit Not Specified when such a marker is documented for this
      sample.
  (3) Pathological phenotype markers without a named disease
      ('tumor', 'lesion', 'metastasis', 'primary tumor').

The condition must apply to THIS sample. The broader GSE topic is
not by itself evidence, many studies include controls, siblings,
or unaffected family members. Use GSE context and sibling
distribution to interpret what the sample text means, not to
override it. If the GSE studies a disease but THIS sample's text
says 'control' / 'healthy donor' / 'non-tumor', THIS sample's
Condition is the control state, NOT the GSE disease. If the sample
text gives no condition signal AT ALL (no disease, no stage, no
control / normal / healthy marker) and the GSE topic alone is the
only cue, output exactly: Not Specified.

EXCLUSIONS (a disease MENTION is NOT this sample's condition):
  - FIELD-LEVEL DENIAL: a disease-named field with a denial value
    (N, No, 0, false, negative, absent, unaffected, none, neg) is
    a denial of THAT field only. Does NOT apply to biomarker /
    receptor / molecular-marker / haplotype fields whose name is
    a gene, protein, receptor, or marker.
  - RELATIONAL: a disease name inside a relational phrase
    ("sibling of", "relative of", "parent of", "child of",
    "family member of", "unaffected ... of", "proband for",
    "control for", "donor for", "healthy donor for") belongs
    to the proband, NOT this sample. Look for THIS sample's own
    `disease state` / `affection_status` field instead.
    DISAMBIGUATION: 'control' / 'healthy' / 'donor' appearing
    AS THIS sample's own state, without a relational phrase
    naming a different subject, IS this sample's Condition. The
    relational rule fires only when a different subject's disease
    follows the relational opener.
  - PRIORITY: an explicit `diagnosis:` / `dx:` / `condition:` /
    `disease state:` / `pathology:` / `affection_status:` /
    `group:` field with a non-empty value WINS, whether the value
    is a disease ('breast cancer') or a control state ('control',
    'healthy', 'normal'), it IS the condition.

REFINEMENT MODE, the user message includes a `Phase 1 value:` line
carrying the verbatim string Phase 1 already extracted for THIS
label. When that value is non-empty and not `Not Specified`, run
the following structural checks IN ORDER and apply the FIRST one
that fires; if none fires, emit the Phase 1 value verbatim.
  Check 1, ACRONYM EXPANSION (purely structural, no prior
    knowledge). If the Phase 1 value is a sequence of N capital
    letters (optionally with internal hyphens or digits), AND THIS
    sample's title/source/characteristics OR the GSE title/summary/
    design contains an N-word phrase whose successive words begin
    with those same N letters in the same order (case-insensitive),
    output that N-word phrase in the form it appears in the text.
    The match is by initial letters only, do NOT use any prior
    knowledge of what the acronym 'usually' means.
  Check 2, FRAGMENT TO FULLER PHRASE. If the supplied text
    contains a longer phrase that literally CONTAINS the Phase 1
    value as a substring AND adds a head noun or anatomical /
    pathological qualifier (e.g. an organ-adjective whose noun
    appears in the title, or a code whose label is supplied by a
    legend in the same field), output the longer phrase.
  Check 3, otherwise, emit the Phase 1 value VERBATIM.
Use NO prior knowledge of what abbreviations conventionally mean,
what brand names map to, what diseases are usually called, or any
expansion that is not literally written in the supplied text. The
REFINEMENT replacement preserves the SAME entity, it never
introduces a different disease, organ, or compound.
When the Phase 1 value is `Not Specified` or empty, ignore this
REFINEMENT MODE block and apply the inference rules below.

Experiment context for THIS sample's GSE:
  Title:   {GSE_TITLE}
  Summary: {GSE_SUMMARY}
  Design:  {GSE_DESIGN}
Sibling distribution for this label across other samples in the same
GSE is provided in the user message. Treat it as cohort evidence, not
as a substitute for THIS sample's own text.

When a characteristics field embeds its own value-to-meaning legend
in the field name (e.g. the field name lists code-to-label mappings
such as "0 = ...; 1 = ...; 2 = ..." before the value), report the
meaning that THIS sample's value maps to in that legend, not the raw
code and not the full legend text. Use only the mapping as it is
written in this sample's own metadata; do not invent codings.

Demographic identifiers, age, sex / gender, race or ethnicity, BMI,
height, and weight, describe the subject, not a clinical state. Do
not place demographic values into the condition output.

If multiple conditions apply to this sample (primary disease plus
comorbidities, additional diagnoses, or co-existing pathologies),
join them with "; " in the order they appear.
